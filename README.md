# Читаю сам — обновления и автоматическая сборка

Репозиторий публикации Android-приложения «Читаю сам: Серебряный лес».

## Статус
- Исходный Android-проект v0.5.1 подготовлен отдельно как `ChitayuSam-source.zip`.
- Workflow: [Android APK — build and publish](../../actions/workflows/android-release.yml).
- Сборка требует **того же ключа**, что использовался на Mac для установленного на Samsung APK.
- До завершения настройки автоматические выпуски **не готовы**. Старый APK v0.5.1 не заменяем.

## Первичная настройка (один раз)

### 1. Добавить исходники в исходный выпуск
Открой [Release v0.5.1](../../releases/tag/v0.5.1) → **Edit release**. Перетащи `ChitayuSam-source.zip` в Assets и сохрани. Имя файла строго `ChitayuSam-source.zip`.

В этом архиве — каталог `android/` с исходным кодом. В нём нет keystore и локальных данных ребёнка.

### 2. Сохранить исходный ключ подписи как GitHub Secret
На **том Mac, на котором устанавливался APK v0.5.1**, открой Terminal:

```bash
test -f "$HOME/.android/debug.keystore" && base64 -i "$HOME/.android/debug.keystore" | pbcopy
```

Если файл отсутствует, не генерируй новый — нужно восстановить исходный ключ с Mac, на котором собиралась установленная версия.

Открой [Settings → Secrets and variables → Actions](../../settings/secrets/actions) → **New repository secret**.

- Name: `ANDROID_DEBUG_KEYSTORE_B64`
- Secret: вставь содержимое буфера клавишами **Cmd+V**, сохрани.

**Никогда не помещай ключ подписи или его base64 в README, issue, коммит, ZIP или чат.** Это старый *debug*-ключ только для частного прототипа. Для более широкого распространения потребуется отдельный production-ключ и план миграции.

### 3. Пробная сборка
Открой [Actions](../../actions) → **Android APK — build and publish** → **Run workflow**.

Укажи `release_tag = v0.5.1`. Ручной запуск **только соберёт** APK и положит его в Artifacts; он **не изменит опубликованный Release**.

Workflow проверяет сертификат подписи с уже опубликованным `ChitayuSam.apk`. При расхождении процесс останавливается.

## Следующие версии
Чтобы выпустить `v0.6.0`, нужно добавить в `overrides/android/` изменённые исходные файлы (пути относительно папки `android/`), затем создать Git-тег `v0.6.0` в этом репозитории. GitHub Actions:

1. Возьмёт исходники из `ChitayuSam-source.zip` в v0.5.1.
2. Применит файлы из `overrides/android/`.
3. Выставит `versionName` и `versionCode` по тегу.
4. Соберёт debug APK с **исходным** ключом Mac.
5. Сравнит сертификат с APK v0.5.1.
6. Опубликует новый GitHub Release с `ChitayuSam.apk` и `ChitayuSam.apk.sha256`.

Приложение не обновляется молча: взрослый проверяет обновление и подтверждает установку на Android.

Если будущие версии потребуют совершенно другой схемы сборки, следует перенести Android-исходники прямо в GitHub и использовать полноценный релизный ключ.
